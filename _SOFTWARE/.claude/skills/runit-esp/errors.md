# Error handling

The design and every macro: [ERRORS.MD](../../../runit-esp/components/core/errors/ERRORS.MD) and [core/errors/AGENTS.md](../../../runit-esp/components/core/errors/AGENTS.md). Who responds to errors: SYS_DEVICE.MD "Error policy". How a reported chain leaves the board: ERRORS.MD "Error record". This file is the checklist that applies in every component.

## Rules

- **Return `err_h`** from anything that can fail; `NULL` = success, never `NULL` for a failure. Every such function is `MUST_USE`.
- **Create and propagate** with the `ERR_*` macros (`ERR_NEW`, `ERR_WRAP`, `ERR_TRY`, `ERR_CHECK`, `ERR_ESP` / `ERR_TRY_ESP` for `esp_err_t`). Vendor and ESP-IDF codes never pass up raw.
- **End a chain once:** `err_report` where nobody returns it any more (task loops, callbacks, boot steps); `err_free` when it is handled; `err_log` only borrows. Code on the reporting path (the connector task, the log hook, the sink) never reports: `err_log` + `err_free`. Never share a cause between two chains; a leaked node shrinks the pool for good.
- **Context goes into the error, not the log:** the payload of the tag carries the ID, pin, value, limits. Drivers don't log.
- **Steps that must all run** (teardown, sweeps, per-channel work) return the first error and free the rest (`ERR_KEEP_FIRST`); report a later one first where it matters.
- **Device errors** are wrapped by the registry (`ERR_DEV_ID{id}`, `ERR_DEV_OP{op, dir}`), so a driver returns plain causes. A driver's own task or listener has no caller and wraps its own error with its ID before reporting it. A device that fails a range check uses `ERR_DEV_RANGE` (SYS_DEVICE.MD).
- **A routed command's errors** are answered and reported with the command (`router` does it); a handler only returns them.
- **A code path that runs every pass or tick reports a standing condition once**, not on every repeat: VM blocks do it per episode (VM_CORE.MD "One report per episode"), PERIODIC per overrun. Each report costs a console log, a record on the errors stream, a slot of the history and a run of the device error policy.
- **Severity follows the consequence.** Each tag has one severity, in its map; a chain is as severe as its most severe node, and wrapping never lowers it. A failure that costs less in one place is handled (freed) there, or gets its own tag. CRITICAL is for faults that must stop the board (the policy stops the VM and suspends every device). A context-only wrapper tag is NONE.
- **New tags** go at the end of the module's `ERR_<MODULE>_MAP` with the next code; a new module takes an ID in `err_modules.h`. Never renumber. Every tag has its user message in the module's `errors/errors_<module>.json`, next to the map (`errors/<component>_errors.h`; `ERR_MODULE_DEFINE` stays in a `.c` the firmware references anyway, or in `errors/<component>_errors.c` with the component linked `WHOLE_ARCHIVE`; otherwise the linker drops the registration), with a `hint` (what the user can do) when the user can act on it (templates/AGENTS.md "Errors"), and a field that names an instance (a device, pin, channel, variable, block, ...) says so there when its name does not. Then `sh templates/sync.sh` (regenerates `errors.json`; it fails on a tag without a message).
- **Control flow never depends on an error being allocated:** when the pool is empty `ERR_NEW` returns the static `ERR_POOL_EMPTY` and `ERR_WRAP` returns the cause unchanged.
